Rust log formatters

For each formatter: the call site on the left, the rendered output on the right. Outputs are captured from real binaries by src/bin/gen.rs; see the source.

Do log and tracing share the same format?

No. Their default formatters produce visibly different strings for the same call — compare the env_logger default with tracing-subscriber's default. The bridge example shows what happens when log::info! is routed through tracing-subscriber via LogTracer: the output uses tracing's format, not env_logger's.

env_logger — default

fn main() {
    env_logger::init();
    log::info!("the answer was: {}", 12);
}
[2026-05-07T18:20:49Z INFO  env_logger_default] the answer was: 12

tracing-subscriber — Full (default)

fn main() {
    tracing_subscriber::fmt().init();
    tracing::info!("the answer was: {}", 12);
}
2026-05-07T18:20:50.076704Z  INFO tracing_full: the answer was: 12

tracing-subscriber — Compact

fn main() {
    tracing_subscriber::fmt().compact().init();
    tracing::info!("the answer was: {}", 12);
}
2026-05-07T18:20:50.252151Z  INFO tracing_compact: the answer was: 12

tracing-subscriber — Json

fn main() {
    tracing_subscriber::fmt().json().init();

{"timestamp":"2026-05-07T18:20:50.595715Z","level":"INFO","fields":{"message":"the answer was: 12"},"target":"tracing_json"}

tracing-log bridge — log::info! rendered by tracing-subscriber

fn main() {
    tracing_log::LogTracer::init().expect("LogTracer init");
    let subscriber = tracing_subscriber::fmt().finish();
    tracing::subscriber::set_global_default(subscriber).expect("set global default");
    log::info!("the answer was: {}", 12);
}
2026-05-07T18:20:50.779598Z  INFO tracing_log_bridge: the answer was: 12
